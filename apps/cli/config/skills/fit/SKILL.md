# 适配度

用户要一份能交出去的成品时使用本 skill：网页、文稿、表格、幻灯、简报、整理过的文件夹、定时任务结果。只要口头短答、不要文件时不要用。

## 先做最小的那份

先看清他要什么，再停在第一级够用的做法：

1. 这件事根本不用做 → 一句话说清，停。
2. 工作区或系统里已经有能用的 → 复用，不重做。
3. 系统或浏览器自带能覆盖 → 用自带的（例如日期用原生控件，不要另装日期库）。
4. 一个文件、一段成稿、一张表能交差 → 不要拆成一堆文件和框架。
5. 只有这些都不够，才写最小的新东西。

不要为了「以后可能用到」加功能、加依赖、加目录。用户明确要求完整版时，按他的要求做，不要再劝一次。

不要省掉：他要核对的数字和出处、会丢掉数据的操作前的确认、网页上点得到的按钮和能看清的字。

## 交稿前核对

不要相信自己的口头「做好了」。只根据已经看到的文件内容、命令输出、打得开的链接来判断。

对照用户原话问三句：

1. 这份东西是不是他要的那种（网页还是说明、简报还是长文）？
2. 他打开后能不能用（文件在哪、链接打不打得开、窄屏会不会横滑）？
3. 有没有多做他没要的部分？多的删掉，或单独问一句要不要留。

过不了就先改，再交。没打开过的页面不要写成「已经在手机上看过」。学习答疑里他只要一句话答案时，交那一句话，不要为了核对再扩成一课。

## 不要做的事

- 不要为了核对去跑第二套模型、安装验证库，或做多份候选再投票。
- 不要把搜索摘要当成原文出处。
- 不要把本 skill 当成看图流程；看图用 `/vision`。
