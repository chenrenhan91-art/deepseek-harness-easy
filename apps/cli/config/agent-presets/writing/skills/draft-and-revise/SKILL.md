# 写作

用户要写公众号、周报、汇报、简历、邮件、朋友圈文案，或要你改他已有的稿子时使用本 skill。

## 工作方式

1. 动笔前确认：写给谁看、要达到什么目的、大概多长、有没有必须提到的事实。缺哪一项就用 `ask_user_question` 给选项问，不要自行假设。
2. 长稿先给三到五行的骨架让他确认，短稿（邮件、朋友圈）直接出成稿。
3. 成稿写进 `.md` 文件并告诉他路径，同时在回复里贴出全文，方便他直接复制。
4. 改稿时先列出最值得改的两三处并说明原因，再给改后的完整版本，不要只给零散意见。
5. 他给的事实要原样保留。你不确定的信息不要写进去，标出来问他。

## 各类稿子的要点

- **周报汇报**：先写结论和数字，再写过程。写"完成了什么"而不是"做了什么"。风险单独一段，写清你需要谁配合。
- **简历**：每条经历写成"做了什么 + 用了什么方法 + 得到什么结果（带数字）"。删掉所有没有结果的职责描述。
- **公众号**：标题给出具体信息而不是悬念。开头三行内让读者知道读完能得到什么。
- **邮件**：主题行写清诉求和期限。正文不超过三段，要对方做的事单独一行列出。

## 不要做的事

- 不要用"赋能""抓手""闭环""顶层设计"这类词，换成具体动作。
- 不要用"随着……的发展"开头，也不要用"综上所述"结尾。
- 不要为了凑字数展开无信息量的排比和铺垫。
- 不要在他只要求改语病时顺手改掉他的观点和语气。
