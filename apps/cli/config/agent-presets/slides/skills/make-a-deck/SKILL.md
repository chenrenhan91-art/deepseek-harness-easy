# 做 PPT

用户要做汇报、提案、分享或答辩的演示文稿时使用本 skill。产出是一个 HTML 文件，浏览器打开、左右键翻页、F11 全屏即可开讲。

## 工作方式

1. 先问清：讲给谁听、有多少时间、听完他们要做什么决定。用 `ask_user_question` 给具体选项。
2. 按时间估页数：一页讲 1 到 1.5 分钟，10 分钟的汇报就是 8 到 10 页，不要多。
3. 先给一页纸的大纲——每页一行标题——等他认可再做成稿。
4. 成稿写进单个 `.html`，键盘左右键翻页，演讲者备注写在每页的注释里。
5. 交付时说明：打开哪个文件、怎么翻页、怎么改文字。

## 每一页的规矩

- 标题写这一页的结论，不要写"项目介绍"这种栏目名。
- 正文不超过 30 个字。放不下就是这一页装了两件事，拆成两页。
- 能画就不写：流程用箭头，对比用左右两栏，占比用一个大数字加一句话。
- 一页最多一张图或一个表。表格超过 5 行就改成图或只留关键行。
- 数字要大，标注要小，来源写在页脚。

## 整份稿的结构

汇报类：现状与问题 → 你做了什么 → 结果（数字）→ 下一步与需要的支持。
提案类：对方的痛点 → 你的方案 → 凭什么是你 → 报价与时间 → 下一步动作。
分享类：一个具体场景开头 → 三个要点 → 一句可带走的结论。

## 不要做的事

- 不要做需要 PowerPoint 才能打开的文件，用户不一定装了 Office。
- 不要用翻页动画和逐字出现效果，上台时容易出岔子。
- 不要把讲稿贴到页面上，那些内容属于演讲者备注。
- 不要在最后放一页只写"谢谢"，最后一页应该留着行动项或联系方式。
